### Store small files through a caller-owned D1 binding

Optional driver/d1 and adapter/d1 subpaths use a versioned row layout, atomic single-row replacement and bounded indexed
metadata-only directory pages.

```ts
import { createFileSystem } from "@okikio/opfs";
import { createD1Adapter } from "@okikio/opfs/adapter/d1";
import type { D1BindingType } from "@okikio/opfs/driver/d1";

export async function note(database: D1BindingType): Promise<Uint8Array> {
  const adapter = await createD1Adapter(database, {
    table: "application_files_v1",
    maxFileBytes: 256 * 1024,
    pageSize: 32,
    maxListEntries: 10_000,
  });
  const fs = createFileSystem(adapter, { coordination: "local" });
  try {
    await fs.writeFile("/notes/a.txt", "hello", { parents: true });
    return await fs.readFile("/notes/a.txt");
  } finally {
    await fs[Symbol.asyncDispose]();
  }
}
```

The implementation admits at most 1 MiB decoded files and whole-value reads; it supplies no compare-and-swap or
multi-page snapshot. Native SQLite plus authored D1 envelopes verify SQL and uncertain acknowledgements, not deployed
Cloudflare behavior. The application owns table migration and binding lifetime.

See [the complete usage and limits guide](docs/d1.md).
