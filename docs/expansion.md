# Storage expansion status

This page is for contributors continuing the storage expansion. Public exports and executable tests are the authority
for implemented behavior. A provider name in a research catalog is not a support claim. Keep work on the consolidated
branch and existing PR until the maintainer decides to merge it; this work does not delete historical branches.

A representative supported flow uploads a ZIP to a disposable GCS-compatible server, binds reads to its generation,
lists its directory, and reads one member through a read-only filesystem view. The caller owns credentials, transfer
checkpoint persistence, key policy and preview rendering. A changed generation fails instead of mixing object versions.
For encrypted content, the optional Tink payload source authenticates complete covering segments before returning
plaintext. A transfer can resume the exact ciphertext saved from an earlier encryption attempt. Reconstructing that
ciphertext from plaintext after losing the encoder state remains unimplemented; a new encryption attempt produces
different bytes. See [encrypted transfer recovery](encryption.md#resume-exact-ciphertext-not-a-new-encryption-attempt).

Native GCS metadata now retains exact decimal metageneration and canonical CRC32C text through client and driver
results. Guarded requests pair the metadata token with an object generation; a returned checksum remains unverified
provider metadata. The pinned emulator reports constant metageneration and cannot establish live guard enforcement. See
the [GCS guide](gcs.md) for the observation, guarded-operation and unknown-publication contracts.

[CMIS](cmis.md) adds a native 1.1 Browser Binding client for typed document properties, bounded original streams and
explicit change-token mutations. Native Apache SDK readback verifies complete bytes; its archival server fixture does
not enforce HTTP authentication. [Classic HDF5](hdf5.md) adds literal root-link indexing and selected contiguous
standard numeric values. The profile refuses unsupported layouts and provides no checksum or netCDF-4 interpretation.

[CouchDB attachments](couchdb.md) preserve literal document/attachment IDs, whole-document revisions and native
acknowledgements. Bounded metadata and exact streamed ranges do not imply a filesystem layout, immutable history or
physical erasure. Official server/SDK tests verify complete bytes and sibling revision conflicts.

[Cryptomator previews](cryptomator.md) authenticate selected format-8 SIV_GCM names and complete covering content chunks
using application-unlocked keys. A nested ZIP can read selected plaintext extents without decrypting unrelated chunks.
This does not establish original EOF, freshness, directory completeness or a name-to-content binding.

[etcd](etcd.md) retains native byte keys, exact revision strings, historical prefix cursors and explicit replacement
lease policy. Native CLI readback verifies complete values and conflicts; a single-node fixture does not qualify
replicated consensus or deployment durability. [HTTP upload draft 15](upload.md) supplies versioned upload descriptors
and explicit reconciliation. Actual client process kills verify recovery after lost append/final replies, while a
missing completed resource remains an unknown publication outcome. It is separate from tus and is not a final RFC.

The current provider qualification uses native ProFTPD/libcurl for FTP, rabbitmq-c for AMQP, libmemcached for Memcached,
and nats.c for JetStream. Their selected local provider cases passed; preserved Python SDK captures remain historical
evidence with their original hashes. Redis and Valkey also passed the native hiredis profile, including a rerun of the
final file-admission and receipt-bound guards. See each capability guide for the exercised operations and exclusions.
These results do not establish live-service or full-group support.

## How to continue

Add each protocol as an import-safe subpath at the narrowest useful layer. A native client can stand alone when its
operations do not supply file semantics; message acknowledgment and cache eviction, for example, do not become files.
Where storage semantics fit, compose client → driver → adapter → filesystem. Add a bridge only for an actual external
consumer contract. Keep protocol messages in the client, storage mechanics in the driver and canonical filesystem
translation in the adapter. Third-party implementations use the same public contracts without registering globals.
Prefer injected capabilities and native Web APIs; selecting a new runtime dependency requires an explicit provenance and
supply-chain review.

For every added capability, document a complete consumer example, exact unsupported behavior, resource ownership,
bounded allocations, cancellation and recovery. Test against an independent producer or provider as well as malformed
and interrupted operations. A fake HTTP response proves message handling; a container proves only the exercised server
behavior. Live-service claims require separately authorized live-service evidence.

The [complete group index](../planning/storage/GROUPS.md) accounts for all 45 proposed owners, current routes and
remaining boundaries. The original research handoff counted 895 catalog records and 136 focused archive/encryption
profiles. Those are discovery inventories, not additive integration counts. The complete
[versioned research handoff](https://github.com/okikio/opfs/blob/b3ed2f7092264e1a5d86358a10bd1f00386466bf/planning/storage/README.md)
preserves every catalog ID, route and format record in a fresh clone. Its historical proposals remain distinct from the
implemented capabilities on this page.

[Memcached](memcached.md) adds classic ASCII cache byte commands, lossless CAS tokens and explicit expiry without a
filesystem projection or persistence claim. [MCAP](mcap.md) adds physical major-0 uncompressed recording inspection,
bounded sparse pages and selected payload/attachment previews. CRC scopes and replay costs remain explicit; compressed
chunks and application payload decoding remain separate work.

[BinHex](binhex.md) preserves separate data and resource forks with bounded sequential replay. A verified data prefix
checks its whole data fork while resource and terminal evidence remain pending. [Shapefile](shapefile.md) reads
explicitly supplied 2D geometry and raw DBF rows, retaining physical ordinals for Null and deleted records. CRS, text
decoding and sidecar discovery remain application decisions. [Pub/Sub](pubsub.md) adds explicit unary message
publication, pull and settlement; uncertain mutations require application recovery rather than hidden retries. Native
qualifications and unsupported profiles are recorded in each guide; these additions do not complete their catalog
groups.

[GeoTIFF](geotiff.md) plans exact uncompressed row spans and reads owned numeric windows, while raw block sources retain
physical padding and bits. CRS declarations remain unresolved; successful reads do not certify COG layout or server
behavior. [QCOW2](qcow2.md) reconstructs selected standalone guest bytes, distinguishing absent mappings and explicit
zeros without a host mount or guest filesystem parser. Its active mapping checks do not establish refcount truth or
payload authentication. [Redis and Valkey](redis.md) share a bounded RESP2 byte client with separate native server
qualifications, explicit expiry and caller-owned recovery after uncertain mutations. These native commands do not supply
record-driver revisions, a filesystem projection or a persistence guarantee.

[JWE](jwe.md) authenticates an entire bounded compact direct-AES-GCM message before exposing an owned plaintext source.
Archive readers can borrow that source until its owner is disposed; a small preview still requires whole-message
authentication and buffering. [NATS JetStream](nats.md) preserves native publication receipts and sequence reads over
exclusive caller-supplied channels. Stream retention and deduplication windows remain deployment policy, and an
unacknowledged publication can have an unknown outcome. [Parquet](parquet.md) reads selected flat physical numeric
columns with separate null masks and per-page checksum evidence. It does not provide a query engine, nested records or
arbitrary codecs. These profiles extend their individual routes rather than completing the broader catalog groups.

[age](age.md) authenticates selected covering payload chunks under a caller-unlocked file key, so an application can
inspect a nested archive without collecting all plaintext. Whole-file verification remains explicit. [ORC](orc.md) reads
selected uncompressed physical numeric columns with separate validity masks and no invented integrity guarantee.
[AMQP](amqp.md) retains native publication confirmations and explicit destructive queue reads; applications own topology
and recovery after uncertain mutations. Each module is optional and has its own limits and ownership contract.

[Kafka](kafka.md) appends bounded binary records and fetches a fully admitted page from an explicit bigint offset in one
selected partition. The application supplies authenticated exclusive channels and retains known receipts or reconciles
unknown append outcomes; there is no automatic broker discovery, retry, consumer group or filesystem projection. The
first profile accepts uncompressed, nontransactional, non-idempotent CreateTime magic-2 batches only. Fresh
Java/candidate full-value comparisons passed in both directions on one plaintext broker, including public metadata and
earliest/latest offset observations in a separate repeat. Deno record/session controls passed independently. TLS/SASL,
multiple brokers, measured allocation peaks and current release package/CI gates remain separate. This advances
`log-kafka`, not the entire `record-store` group.

[Arrow IPC](arrow.md) adds indexed file and forward-stream previews for six flat uncompressed V5 little-endian types.
Opening compares embedded/footer schemas and admits index geometry; selected reads validate only the requested column
payloads. Streams consume bounded bodies in order, cancel on early return and do not provide durable resume state.
Native originals cover ten file/stream profiles, including nulls, empty batches, int64 extrema, UTF8 and binary values.
This advances `format-arrow`; it does not complete Feather, dictionary, compression or the entire dataset group.

[Glacier vaults](glacier.md) add original vault/archive REST operations, explicit retrieval jobs, completed-output byte
sources and native multipart mechanics. Retrieval is potentially billable and output availability can expire. Callers
own durable receipts and reconcile unknown outcomes; no automatic paid job, OPFS projection, S3 Glacier storage-class
qualification or durable transfer checkpoint is implied. Authored source/packed-consumer checks and independent
SDK/native/live proof are distinct gates.
