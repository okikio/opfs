# Test and benchmark review inventory

This inventory explains why the permanent validation files exist and records their review disposition. It complements
[validation.md](./validation.md), which owns commands and proof limits. Tests protect observable storage behavior;
benchmark byte oracles run before timing and do not turn timings into correctness evidence.

These synthetic storage sizes identify primitive/layer costs and boundary behavior. They are not a representative
application trace, remote cloud SLA, or universal regression threshold. No performance claim should be inferred from a
smoke run on a shared workstation.

The report collector allows sixty minutes for the complete provider program, which itself runs two serial programs with
twenty-minute watchdogs and acquires disposable services. These generous limits bound a broken command; they are not
throughput targets or provider health thresholds. Browser fixture release now attempts database deletion and all other
owned releases even after a close or drain fails. Actual Node failure controls established that several separate
`TestContext.after` hooks can skip later hooks or hide cleanup failures, so fixtures with several owners use one
explicit release scope.

The opaque-origin assertion follows the [Storage Standard](https://storage.spec.whatwg.org/#obtain-a-storage-key): an
opaque origin cannot obtain a storage key. The
[File System Standard](https://fs.spec.whatwg.org/#dom-storagemanager-getdirectory) requires `getDirectory()` to reject
with `SecurityError` when that storage acquisition fails. The test checks exposed capabilities instead of choosing a
policy by browser brand.

## Supporting files and repository output

Deno tasks, `.mise/tasks/` delegates, `deno.json`, `package.json`, `mise.toml`, TypeScript realm configurations,
`.npmrc`, `pnpm-workspace.yaml`, lockfiles and all three GitHub workflows were inspected as command/ownership guidance.
The release runtime suite and its fixtures remain under `.mise/tasks/release_test.ts`; release consumer probes remain
under `.mise/tasks/release-consumer.ts`. Packaging, schema and release implementations remain build support, not
alternate production imports or test frameworks.

The ignore file now names this repository's actual dependencies, outputs, local credentials, editor files and OS
metadata. Removed obsolete Rails/Ruby/Astro/NextJS and unrelated Polar/frontend-template rules. Existing local archives,
coverage output, `.release/`, `.tmp/`, `.agents/`, node_modules and `scripts/deno.lock` remain ignored and were
retained. The source `deno.lock`, fixture source, Dockerfile and reproducible example environment configuration remain
visible. No required fixture or tracked generated input was discarded; no new raw execution log belongs in the source
tree.

Static checks, release packaging and installed-consumer checks still require CI or an isolated runner with a memory
budget. Local runtime, lint, formatting, browser and disposable-provider evidence cannot substitute for those gates.

## Prior retained validation

The following retained results describe the earlier source checkpoint. The renewed fixture ownership and command
watchdog changes require fresh runtime, browser, provider, package and static gates; these historical counts do not
establish that the changed fixtures have passed those gates.

That checkpoint passed `deno task test`, `test:node`, `test:bun` and the five-repeat shuffled `test:stress` lane. The
three-browser suite passed 51 cases with six named capability/instrumentation skips. Disposable providers passed eight
cases; installed ecosystem consumers passed seven. `test:linux` passed all five runtime/storage lanes. The real
Mountpoint/BlobFuse lane passed 22 cases.

In a disposable Linux copy with a 2 GiB memory limit, `deno task quality` and `deno task verify:npm` passed against
actual dependencies. This includes static/schema/browser-realm checks, documentation lint, canonical coverage,
publication dry-run, packaging, installed declarations and Deno/Node/Bun consumers. Canonical isolated coverage exported
LCOV and HTML without the missing-transpiled-source warnings seen in the supplemental workstation export.

The final serial `bench:report` receipt passed eight programs and 76 Mitata cases plus the lifecycle observation, with
all 111 input hashes unchanged. Browser measurements passed 55 lanes with 495 samples across eleven reports and one
WebKit OPFS capability skip. Disposable provider measurements passed 26 Node and 13 Bun cases. Container-mounted
filesystem measurements passed sixteen runs across both providers, four layers and two operations. These checks
establish result/sample validity, not a universal latency budget.

Deno 2.9.7, Node 26.10.0 and Bun 1.3.14 supplied host evidence. Linux compatibility lanes additionally used Node 22.18
and 24.21. That isolated run did not exercise Windows; the CI host matrix owns Windows evidence. Original staged changes
and ignored local evidence were preserved.
