# Start with the intended result

Identify who will use the result, what they need to do and which decision the work must support. Then inspect the source and choose the smallest step that can resolve a consequential unknown.

Read current repository instructions and the [shared quality guide](../../guides/software-quality.md), then select the capability whose decisions change. A familiar framework name does not identify the task owner. Trace the actual entrypoint and caller before adding companions.

Use existing context to resolve technical details. Ask the user only when an unresolved human choice changes the intended outcome, authority or material tradeoff. Keep independent authorized work moving while a prerequisite is unavailable.
