# Route project instructions to the guidance

Merge a short route into the repository's existing instruction file. Resolve the links for the actual installation, fill project facts from verified sources and retain existing scope rules. This fragment does not install a host configuration by itself.

The following text is a template. Replace each bracketed value before adoption:

```text
Use [guidance root]/START.md to select the capability for the requested task.
Read the selected skill and its shared software-quality guide. The guides own
shared methods; references provide technical detail; the handbook explains
project operation; its playbook sequences procedures and evidence gates.

Follow this repository's current instructions and decision records. Inspect
actual source, public exports and consumers before treating a document as
implemented behavior. Use [runtime and versions], [task entrypoint] and
[supported environments]. Do not add a runtime or deployment system solely
because a guidance example uses it.

Start substantial work with the intended user action, consequential question,
existing evidence and smallest relevant authorized probe. Keep one task record
at [existing record location]. Carry decisions, source identities, actual check
results, active operations and the next action through interruptions.

Use the generic profile unless this repository explicitly selects another
contract. Run the relevant component, artifact and user-flow checks for the
claimed behavior. Preserve existing authorization for the same action and
destination. Report unavailable requirements and unrun checks precisely.
```

After merging, verify every path and named command. Start a fresh session in the intended host and check that a real task uses the route. Keep exact package choices, environments, ownership and release permissions in the project; avoid copying them into generic shared guides.
