# Keep a usable project record

Use these templates inside the project's existing record system. Fill only fields that affect the task. Keep one source for each fact and link evidence rather than copying competing summaries.

Skills: `plan-changes`, `write-docs`.

| Record | Use it for |
| --- | --- |
| [Identity](identity.md) | Outcome, source, constraints and first value. |
| [Acceptance](acceptance.md) | Exact user or caller action and observed checks. |
| [Ownership](ownership.md) | Components, resources, state and consumers. |
| [Prerequisites](prerequisites.md) | Missing results, owners and independent work. |
| [Commands](commands.md) | Verified procedure-to-command bindings. |
| [Engineering evidence](ci.md) | Selection, caching, builds and measurement. |
| [Services](services.md) | Consumer-specific readiness and invalidation. |
| [Models and runners](models.md) | Actual capability, quality, resource and execution contracts. |
| [Delivery](delivery.md) | Candidate, publication, preview, production and cleanup identities. |
| [Incidents](incidents.md) | Failures, partial state, recovery and prevention. |
| [Examples](scenarios.md) | How the same records scale to a library, CLI or application. |

Reference secrets by role or secure location. Keep personal payloads and private operational evidence in their approved storage. A public handoff should contain the information its audience needs without exposing credentials or unrelated source history.
