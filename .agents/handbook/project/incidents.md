# Record an incident without hiding uncertainty

Preserve enough evidence to choose a safe next action and prevent the same failure. Keep private payloads and credentials out of public records.

| Field | Value |
| --- | --- |
| Symptom and affected user action | |
| First failed operation and observation time | |
| Source, artifact, configuration and target identities | |
| Actual state, active work and known partial effects | |
| Cause, supporting evidence and confidence | |
| Alternative explanations or unknowns | |
| Repair or recovery action and authorization | |
| Rechecked behavior and remaining limit | |
| Cleanup and retained resources | |
| Prevention or detection change, owner and completion condition | |
| Fresh-install, example and procedure consumers updated | |

Keep committed, checked, published, running and user-accepted states separate. A repaired symptom does not establish its cause. Attribute an incorrect assumption, an external constraint and a later change of requirement accurately.

Use [recovery](../procedures/recovery.md) for stateful failures and [procedure maintenance](../procedures/maintenance.md) to repair the instructions that another operator will follow.
