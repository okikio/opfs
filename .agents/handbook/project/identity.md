# Project identity and first value

Record the outcome and current authority before choosing a large implementation. Use the [first-value explanation](../start/first-value.md) to connect the customer, user and system views.

| Field | Value |
| --- | --- |
| Intended user or team | |
| Problem and requested outcome | |
| First useful action and starting state | |
| Decision the work must support | |
| Source repository or material, branch and revision | |
| Current instructions and relevant decisions | |
| Existing local changes and concurrent work | |
| Owned scope and explicit constraints | |
| Supported runtime, hosts and task interface | |
| Existing evidence and consequential unknown | |
| First relevant probe or exact blocker | |
| Next action, owner and acceptance evidence | |

Separate current facts from proposals. If an unknown is safe to carry temporarily, record its consequence and the condition that will resolve or revisit it. A source revision identifies inspected content; it does not prove that the content is published or active.
