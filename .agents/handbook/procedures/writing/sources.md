# Bind instructions to current sources

Use the target repository's current implementation, command help, configuration schemas and decision records to establish what an operator can do. Use official provider or runtime documentation for the applicable version and account contract. Preserve a source's date and scope when it can change the conclusion.

| Source | Appropriate use | Limit |
| --- | --- | --- |
| Current source, exports and tests | Find owners, accepted inputs and expected behavior. | Unexecuted code inspection does not prove runtime behavior. |
| Native command help and configuration | Bind supported arguments, defaults and operation forms. | A wrapper or another version can change behavior. |
| Official service and runtime documentation | Check supported contracts and prerequisites. | Account, region, version and consumer behavior still need verification. |
| A recorded operation | Establish the observation under its exact conditions. | A past success does not prove changed inputs or environments. |
| A proposal or design record | Explain intended choices and tradeoffs. | It does not establish implemented controls. |

The collection's [documentation reference](../../../references/docs.md), [readability guide](../../../guides/readability-and-ownership.md) and [product sources](../../../guides/product/sources.md) supply reusable writing and evidence methods. They do not replace the source needed to bind a specific operational command.

Keep public guidance free of private incident payloads, personal storage links and credentials. Preserve attribution and license terms when retaining third-party material. If evidence cannot be shared, state the supported public rule without implying that readers can reproduce an inaccessible report.
