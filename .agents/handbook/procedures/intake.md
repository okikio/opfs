# Open the project and report prerequisites

Use intake for an unfamiliar project, changed environment or consequential new requirement. The result is a concrete outcome, a verified starting point, the first useful probe and known owner actions.

Read current repository instructions, the [generic profile](../profiles/generic.md) and the selected capability. Preserve local work. Determine whether this is a new installation, ordinary change or recovery before choosing an operational path.

| Step | Action | Expected observation |
| --- | --- | --- |
| 1 | Check the actual branch, revision, worktree and concurrent writers. | A recoverable starting state with divergence identified. |
| 2 | Define the first useful user or caller action. | Inputs, visible result and required integrations are explicit. |
| 3 | Extract consequential unknowns and inspect the nearest owner. | A direct probe that can change the next decision. |
| 4 | Map the real consumers, process roles, data and external effects. | No required worker, migration, callback or package consumer is hidden. |
| 5 | Inspect existing dependencies, native tooling and platform outputs. | Reusable contracts and concrete gaps are distinguished. |
| 6 | Check the access needed for the next work with the intended identity. | Local, CI and runtime capabilities have separate evidence. |
| 7 | Report known prerequisites and continue independent work. | Each missing result has an owner, effect and verification step. |

Start a relevant small probe without waiting for an exhaustive inventory. Before creating maintained infrastructure or a fork, identify the requirement and the existing capability that cannot meet it. A copied version floor or scaffold is not evidence of a product need.

A useful owner request names the exact package, publication, export, permission, environment or runtime capability that is missing. State the test that will verify the result. Reference credentials by role or secure location, never by value.

For parallel work, give each writer an exclusive scope and assign one integration owner for shared contracts, manifests and locks. Parallelize independent reads and checks. Coordinate mutations, migrations and shared state through their actual ownership mechanism.

Exit when the outcome, current source, questions, first observation or precise blocker, planned next step and known owner actions are usable. Preserve unresolved questions instead of filling them with assumptions. Use the [project record](../project/README.md) for the fields the task needs.
