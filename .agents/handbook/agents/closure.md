# Close the failure in fresh-install instructions

A live repair can leave stale defaults or recipes that recreate the defect. Trace the changed contract through schemas, runtime defaults, tasks, examples, setup, recovery and acceptance checks.

Update the owning rule and its consumers together. Keep one authoritative default where possible. Separate broadly valid behavior from a particular host's requirement.

Recheck the original failed action within the task's authority. Then inspect or exercise a fresh configuration without relying on the repaired instance's override. Use an independent rehearsal when practical, with disposable resources and a cleanup owner.

Record source review, automated checks and live rehearsal as different evidence. If a required rehearsal remains unavailable, name the owner and remaining case. A committed repair does not establish that every installation path works.

Preserve the symptom, cause confidence, repair, prevention control, recovery and residual limit. Feed the lesson into [procedure maintenance](../procedures/maintenance.md) and the [failure record](../failures/record.md) without copying private incident payloads into generic guidance.
