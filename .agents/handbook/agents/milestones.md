# Give each milestone an observable exit

Choose milestones by the decision or useful behavior they establish. Keep one integration owner responsible for reconciling the whole outcome.

| Milestone | Observable exit |
| --- | --- |
| Intake understood | Current source, intended action, consequential questions and owner actions are recorded. |
| First uncertainty reduced | A relevant observation supports a decision or identifies a precise remaining blocker. |
| Plan executable | Real owners, commands, inputs, outputs, failures and acceptance checks support the next change. |
| Capability verified | The selected artifact or consumer produces the required result under stated conditions. |
| Delivery accepted | The intended reader can use the result, with applicable limits, ownership and recovery. |

A deployment project may add preview and production milestones. A research or library task may finish earlier in the sequence. Do not label implementation activity as proof of the user's outcome.

Delegate independent investigations or exclusive file scopes when that saves time or improves review. Assign one owner for shared manifests, locks, schemas and integration. Reconcile agent findings against current source and tests before adopting them.

Track conflicting evidence and newly discovered work explicitly. Preserve meaningful intermediate results while keeping the remaining acceptance criteria visible. A completed subtask does not close an unrelated requirement.
