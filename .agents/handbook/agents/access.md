# Prove the needed access and report the missing result

Inspect the agreed repository, environment and service-specific configuration sources before declaring a credential or capability absent. Limit discovery to the task's scope.

Keep four results separate: a credential exists, the operator can retrieve it, the intended job can use it, and the destination accepts the required operation. A missing local file does not establish that the deployed application is unconfigured. A read error leaves state unknown.

Test access through the actual supported interface without printing secret values. Distinguish missing scope, expiry, entitlement, network and runtime constraints. Preserve the smallest useful error and non-secret request identity.

Report a concrete owner action as soon as it becomes known: the package and export to publish, the native generation job, the repository access to grant or the capability to enable. Include its verification and the work that can continue independently.

Reuse authorization already established for the same action and destination. When a genuinely new action needs a human decision, prepare the reviewable result first and explain the remaining choice. A procedure or historical command does not grant new authority by itself.
