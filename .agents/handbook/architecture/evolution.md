# Add automation in useful increments

Automate a verified repeated operation after its inputs, outputs, failures and ownership are understood. Begin with the smallest step that removes a demonstrated source of delay or error.

An increment might bind an existing command to a repeatable task, add a missing artifact check, automate temporary-resource retirement or connect a known user-flow test to the selected candidate. Each increment needs an observable result and a recovery path.

Keep proposals distinct from existing capabilities. A document that describes per-change previews, automatic promotion or job isolation does not establish that any of them exist. First inspect the repository's current command and state contracts, then identify the missing behavior.

Make one owner responsible for each maintained mechanism. Prefer a native supported operation over another layer that duplicates selection, caching or deployment state. Evaluate alternatives by the same acceptance criteria and maintenance cost.

When replacing an old path, migrate its callers, exports, tests, examples, configuration and persisted data where applicable. Verify the replacement through a real consumer before removing the previous owner. Keep exceptions tied to a current contract, owner and revisit condition instead of copying historical waivers into templates.
