# Learn from the failing contract

Use observed symptoms and current state to choose the next diagnostic action. Historical patterns can suggest a question, but they do not establish the cause of a new failure.

Skills: `review-code`, `release-software`, `verify-behavior`.

| Need | Read |
| --- | --- |
| Locate the earliest causal failure | [Diagnosis](diagnosis.md) |
| Preserve the incident and close its repair | [Record and closure](record.md) |
| Review recurring assumptions and process gaps | [Retrospectives](retrospectives/README.md) |
| Recover external or durable state | [Recovery procedure](../procedures/recovery.md) |

This chapter contains generic diagnostic questions and record formats. It does not contain a private incident archive or claim that these scenarios have been exercised in the adopting project.
