# Archive and encrypted-content preview planning

This handoff is for OPFS maintainers designing a caller-controlled preview API and for third-party implementers building archive, envelope, vault, repository, and image readers. It proposes contracts and routing for the supplied 136-record checkpoint. It does not add format support or select dependencies.

The machine companion is [preview-routing.json](preview-routing.json). It retains every input record under `source_record`, including stable IDs and all evidence/decision fields, and retains the complete original catalog crosswalk. Independent equality assertions confirmed all 136 source records and the crosswalk were preserved. The original 895-record catalog remains a separate parent catalog; this report neither replaces it nor claims 136 new storage providers.

## A representative user flow

A caller opens a remote ZIP and asks to browse its names, then previews the first 32 KiB of one member. The source supplies stable revision-bound reads. A planner identifies the exact container, compression, encryption, and source capabilities; reports whether names are accessible, how member bytes can be reached, and what work is required before bytes can be trusted. The caller accepts explicit I/O, memory, decoded-byte, CPU, and staging budgets. The operation lists entries without extracting them. Reading a member may use an indexed compressed extent but still need to decompress from that member's beginning. Closing the preview releases its decoder and requests. A missing key, changed revision, exceeded budget, unsupported compression method, or incomplete authentication returns a concrete outcome and recovery choice.

Preview is therefore six independent operations: identify, list, metadata, prefix, range, and verify. Recognition does not imply listing, listing does not imply decoded member access, and returning selected authenticated chunks does not establish whole-file completeness. Applications own thumbnails and rendering; a package reader owns bounded bytes, metadata, and truthful integrity evidence.

## Primary-source checks that change the contract

- ZIP central-directory access and ZIP64 are container/index capabilities, not universal support for all compression or encryption methods. An index can locate a compressed member while a byte range within its decoded content still requires decoding earlier content. See [PKWARE APPNOTE](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT).
- WinZip AES protects member contents, leaves names visible in the ordinary profile, and authenticates the encrypted compressed member with a trailing authentication value. A caller cannot call an early plaintext prefix authenticated merely because AES-CTR permits seeking; checking the member MAC entails reading its required ciphertext extent. See [WinZip AES specification](https://www.winzip.com/en/support/aes-encryption/).
- CMS AuthEnvelopedData explicitly requires integrity verification before releasing information and destruction of plaintext on failure. A streaming decrypt implementation alone is insufficient for a trusted early-prefix API. See [RFC 5083, section 2](https://www.rfc-editor.org/rfc/rfc5083.html#section-2).
- age supports authenticated chunk seeking after header/key setup; seeking relative to EOF must first validate the final chunk. A selected valid chunk still does not certify every other chunk. See [age specification](https://age-encryption.org/v1). Its current editor document includes recipient extensions beyond older summaries, so recipient support needs exact IDs and versions rather than a single generic age capability claim.
- Tink AES-GCM-HKDF streaming is segmented and supports segment-level random access, subject to header, parameters, key derivation, and exact segment boundaries. See [Tink AES-GCM-HKDF streaming](https://developers.google.com/tink/streaming-aead/aes_gcm_hkdf_streaming).
- Authenticated chunks do not always imply independent random access. Libsodium secretstream has message sequence state and rekeying; a route cannot infer independent seeking from its streaming property. See [secretstream documentation](https://libsodium.gitbook.io/doc/secret-key_cryptography/secretstream).
- Solid RAR reuses prior dictionary state. Container version, compression algorithm version, dictionary limit, solid grouping, encrypted headers, and volume availability all affect feasibility. The current RAR specification distinguishes newer compression algorithm revisions, so “RAR5 supported” is an insufficient codec promise. See [RAR technical note](https://www.rarlab.com/technote.htm).
- Seekable Zstandard is a distinct indexed profile; ordinary Zstandard streaming is not equivalent. Independent frame boundaries and the seek table determine useful reads. See [seekable Zstandard format](https://github.com/meta/zstd/blob/dev/contrib/seekable_format/zstd_seekable_compression_format.md).

These sources were inspected for material preview constraints. The entire set of 136 supplied records and 14 implementation descriptions was not independently recertified, nor were any codecs or tools run. Per-ID route classification is architectural inference from the supplied evidence unless a primary check is noted above. No speed, interoperability, or implemented-support guarantee follows.

## Cost, trust, and lifecycle contract

A route reports direct/indexed access, decode from member start, solid-group replay, sequential scan, explicit staging, locked, unsupported, or unknown. It separately measures source bytes, request count, parsed index bytes, compressed bytes decoded, ciphertext authenticated/decrypted, plaintext produced, decoder/KDF memory, replay work, CPU/time, and nesting/reference depth. Estimates may be unknown; actual work must remain within caller budgets. A budget failure must not silently widen the operation into full download, full extraction, password search, or unbounded spool.

Integrity results name their mechanism, scope, and status: parsed-only metadata, checksum pending/passed, member MAC passed, authenticated chunk, full envelope authenticated, signature verified against a caller-owned trust policy, or unauthenticated legacy content. Header visibility and header authentication are separate. Whole-member/message authentication may require reading the whole relevant ciphertext even when decompression can stop early. Stage ciphertext or plaintext only under explicit policy and quotas; the safe default never emits unauthenticated encrypted plaintext as trusted preview data. Formats without authentication cannot gain it through an API label.

All dependent reads need a stable object revision or repository snapshot, including external base images, thin archive members, linked manifests, and backup parent chains. Caller-supplied resolvers control external references; they do not authorize arbitrary network access or host paths. One operation owner closes decoders, owned readers, key operations, and spools on success, failure, abort, or early return. Borrowed sources remain borrowed. Nested archives share aggregate limits.

Preserve duplicate names and raw entry identity. A filesystem-like tree is a projection policy, not proof an archive has filesystem semantics. Never normalize distinct entries into silent overwrite, follow links implicitly, or execute content during inspection.

## Coverage and extension boundaries

The machine file assigns each record an owner and provisional access class, including non-preview primitives, signatures, provider controls, and encoding-only records. The catalog must distinguish these from actual content readers. TAR can often skip uncompressed payload extents but listing remains sequential; compressed TAR adds decompression and extension metadata costs. Solid 7z/RAR can require replay from an earlier group boundary. Encrypted headers can block names before member access. Disk images expose blocks, not automatically a supported inner filesystem. Vaults need format-specific namespace and block/filename authentication. Repository and preservation packages may need manifests, parent chains, chunk indexes, and external references rather than a single archive parser.

Third-party packages should publish explicit descriptors and factories, not self-register through imports. Separate pure detection/parsing/indexing from effectful source, key, resolver, decoder, and spool ports. An extension states exact profiles, operation support, integrity semantics, runtime prerequisites, license/dependency graph, and bounded-work behavior. OPFS runs the same conformance harness against an in-tree implementation and an external implementation. Unsupported stays explicit rather than silently delegating to a host command.

For hot indexes, keep numeric offsets, lengths, codec IDs, and group relationships separate from cold decoded names and rich metadata when measurement supports it. Lazily materialize public entry objects. Retain raw bytes and parse state with clear lifetimes; do not claim typed arrays alone establish cache efficiency. Streaming parsers should consume bounded input and explicit state, returning records, need-more-input, or structured errors, with no hidden I/O.

## Acceptance evidence to plan

Require exact-profile golden fixtures and independent reader/writer interoperability; malformed sizes, index offsets, codec/KDF parameters, truncation, split-volume gaps, wrong keys, tamper, duplicate names, and path/link projection tests; every-byte chunk-boundary invariance; slow sources/sinks and backpressure; early-return/abort resource closure; changed source revisions; shared nested/ref budgets; and installed-package import/runtime checks. Authentication tests must distinguish selected segment, full member, full envelope, and whole object completeness.

Benchmarks must measure list/metadata separately from first-member and late-member preview. Include indexed versus sequential sources, solid versus non-solid, encrypted-header unlock, cold/warm indexes, and staging quotas. Record raw work counters, peak and retained memory, and latency distributions beside throughput. A fast early prefix is invalid evidence if its bytes were not authenticated as the result claims.
