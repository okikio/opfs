# bundlejs-api source review for OPFS planning

Reader: an OPFS maintainer deciding which existing personal code to adapt, which dependencies require review, and which preview promises can actually be delivered.

## Evidence and limits

Reviewed public repository `okikio/bundlejs-api` at exact main HEAD **34be097f00db4bf179b1dc08fc405dcad146905f**, fetched through GitHub API. All links below pin that commit. Source was read only; no packages, builds, tests, benchmarks, or WASM were executed. OPFS source comparison is the current local `src/stream.ts`, on `codex/release-2026-10-06`, clean when inspected. This review is not a binary security audit or a claim that either project passes its tests.

## What exists

The project's purpose is npm bundle-size inspection. Its archive implementation serves package fetching and a build-time virtual filesystem. The compression, utilities, and core workspaces declare local/private `0.0.0` packages; this review establishes source availability, not published stable package availability. [compress package](https://github.com/okikio/bundlejs-api/blob/34be097f00db4bf179b1dc08fc405dcad146905f/compress/package.json), [utils package](https://github.com/okikio/bundlejs-api/blob/34be097f00db4bf179b1dc08fc405dcad146905f/utils/package.json), [core package](https://github.com/okikio/bundlejs-api/blob/34be097f00db4bf179b1dc08fc405dcad146905f/core/package.json).

Useful candidates for deliberate adaptation are strict header parsing, classification data, explicit detection reasons, and precompiled-WASM injection. These are distinct from approving a dependency or copying its implementation.

### Archive classification and parsers

`utils/archive-spec.ts` exposes structured parsing results for Content-Type, Content-Encoding, and Content-Disposition. `utils/archive-detect.ts` separates compression wrappers from archive containers, URL/header hints from wire-byte evidence, and detection from policy. It includes filename aliases, magic signatures, ustar sniffing, reasons, confidence, and diagnostic formatting. This is useful design precedent for inspectable, mostly pure metadata functions and catalog-driven detection. A detected signature does not establish archive validity, authenticated content, supported extraction, or safe resource use. [strict parsers](https://github.com/okikio/bundlejs-api/blob/34be097f00db4bf179b1dc08fc405dcad146905f/utils/archive-spec.ts), [classification and evidence types](https://github.com/okikio/bundlejs-api/blob/34be097f00db4bf179b1dc08fc405dcad146905f/utils/archive-detect.ts#L80), [byte classifiers](https://github.com/okikio/bundlejs-api/blob/34be097f00db4bf179b1dc08fc405dcad146905f/utils/archive-detect.ts#L637).

The response classifier needs a separate lifetime review before reuse. `detectArchiveFromResponse` tees its input; `peekStreamBytes` stops at a prefix limit and releases its lock, without canceling the sniff branch. The other branch is returned for consumption. By standard tee behavior, an abandoned branch can retain subsequently pulled bytes. This is a source-derived potential retention problem, not a measured leak. Merely adding `await sniffBranch.cancel()` before handing off the other branch can also wait for the other branch's termination, so the repair needs an ownership design and tests rather than an unexamined cancellation call. Prefer one reader with prefix replay, bounded admission, explicit cancellation, and accounting for oversized upstream chunks. [prefix read](https://github.com/okikio/bundlejs-api/blob/34be097f00db4bf179b1dc08fc405dcad146905f/utils/archive-detect.ts#L793), [response tee](https://github.com/okikio/bundlejs-api/blob/34be097f00db4bf179b1dc08fc405dcad146905f/utils/archive-detect.ts#L896).

### TAR extraction is an application plugin

`utils/tar.ts` only reexports `@std/tar`. The real application logic is `core/plugins/tar.ts`. It couples archive handling to esbuild, request context, logging, fetch caching, VFS storage, package manifests, npm/CDN resolution, mounts, and package entry selection. Mount/inflight state belongs to the application's context. Reusing that plugin wholesale would pull unrelated package-building behavior into OPFS. [std reexport](https://github.com/okikio/bundlejs-api/blob/34be097f00db4bf179b1dc08fc405dcad146905f/utils/tar.ts), [plugin imports and ownership](https://github.com/okikio/bundlejs-api/blob/34be097f00db4bf179b1dc08fc405dcad146905f/core/plugins/tar.ts).

`fetchAndExtractTarball` fetches a TAR and accepts gzip or uncompressed content, explicitly rejecting other detected compression and non-TAR containers. It pipes into `UntarStream`, reads every file member into a Blob and ArrayBuffer, writes all members into the VFS, and parses package.json. The total extracted size is a counter, not an enforced quota. This is streaming input followed by complete member materialization and complete extraction. It does not implement ZIP member access, encrypted archives, lazy selected-member extraction, or random-access preview. [fetch/detect/decode/extract](https://github.com/okikio/bundlejs-api/blob/34be097f00db4bf179b1dc08fc405dcad146905f/core/plugins/tar.ts#L525), [materialization](https://github.com/okikio/bundlejs-api/blob/34be097f00db4bf179b1dc08fc405dcad146905f/core/plugins/tar.ts#L644).

### Codec modules have whole-buffer public contracts

`compress/mod.ts` statically reexports codec namespaces and facade operations, while the facade also selects codecs through dynamic imports. Separate codec export paths exist. This does not establish that all WASM binaries compile at root import; their bytes are lazily obtained in inspected code. Deep entrypoints still need dependency-graph tests. [exports](https://github.com/okikio/bundlejs-api/blob/34be097f00db4bf179b1dc08fc405dcad146905f/compress/mod.ts), [export map](https://github.com/okikio/bundlejs-api/blob/34be097f00db4bf179b1dc08fc405dcad146905f/compress/package.json).

The compress/decompress facade takes arrays, maps all inputs, and uses Promise.all for full output buffers. Native gzip internally uses Web Streams but finishes with Response.arrayBuffer(). There is no exposed incremental codec stream, bounded concurrent byte budget, or AbortSignal in these inspected operations. Missing native gzip support falls back to returning the original input while retaining the requested gzip result type; OPFS must instead expose unsupported capability or an explicit selected fallback. [compress facade](https://github.com/okikio/bundlejs-api/blob/34be097f00db4bf179b1dc08fc405dcad146905f/compress/compress.ts#L65), [decompress facade](https://github.com/okikio/bundlejs-api/blob/34be097f00db4bf179b1dc08fc405dcad146905f/compress/decompress.ts), [gzip buffering](https://github.com/okikio/bundlejs-api/blob/34be097f00db4bf179b1dc08fc405dcad146905f/compress/deno/gzip/mod.ts#L15).

Brotli and LZ4 source retain denosaurs provenance; Zstd names bokuweb zstd_wasm 0.0.20. The module wrappers cache WASM bytes/initialization in mutable module state. Zstd imports an Emscripten-style generated module and exposes context create/free and dictionary operations, but its inspected compression operations still copy full inputs and outputs through WASM memory. Generated support code has environment access and initialization state. These modules are not automatically pure or caller-isolated merely because their public wrappers are short. [Brotli](https://github.com/okikio/bundlejs-api/blob/34be097f00db4bf179b1dc08fc405dcad146905f/compress/deno/brotli/mod.ts), [LZ4](https://github.com/okikio/bundlejs-api/blob/34be097f00db4bf179b1dc08fc405dcad146905f/compress/deno/lz4/mod.ts), [Zstd contexts and initialization](https://github.com/okikio/bundlejs-api/blob/34be097f00db4bf179b1dc08fc405dcad146905f/compress/deno/zstd/mod.ts), [generated Zstd runtime](https://github.com/okikio/bundlejs-api/blob/34be097f00db4bf179b1dc08fc405dcad146905f/compress/deno/zstd/zstd.deno.js).

All three WASM wrappers accept caller-provided compiled WebAssembly.Module values. That is useful for Workers restrictions on dynamic compilation, but OPFS should prefer an explicit codec factory with owned instance lifetime, initialization failure propagation, and isolated resource state. Embedded/generated WASM and copied upstream bindings remain third-party implementation artifacts even inside a personal repository. Record source revision, license, build toolchain, binary digest, reproducibility evidence, and transitive graph before selecting them. [WASM build task](https://github.com/okikio/bundlejs-api/blob/34be097f00db4bf179b1dc08fc405dcad146905f/compress/scripts/build-wasm.ts).

The utils package manifest has numerous dependencies, including std packages, @nick/dispose, @okikio/undent, @opentf/obj-diff, json5, and resolve.exports. Core also brings esbuild/esbuild-wasm and package-building dependencies. A narrow parser subpath's actual transitive graph must be measured separately; the package manifest alone neither proves all dependencies are loaded nor proves their absence from a bundle. [utils dependencies](https://github.com/okikio/bundlejs-api/blob/34be097f00db4bf179b1dc08fc405dcad146905f/utils/package.json), [core dependencies](https://github.com/okikio/bundlejs-api/blob/34be097f00db4bf179b1dc08fc405dcad146905f/core/package.json).

## Standard-library comparison

Current std/tar manifest reports 0.1.10 with root, tar-stream, and untar-stream exports. Its UntarStream documentation marks the API unstable, supports ustar plus numeric size extension, and requires each entry stream to be consumed or canceled before proceeding. Decompression is separate. The implementation's member cancellation drains that member to advance sequentially, so skipping a later TAR member still costs preceding wire bytes; it is not range seeking. This is suitable to evaluate for a constrained sequential TAR bridge, not a claim of complete TAR dialect support or cheap random access. These are current main source observations, not a pinned release audit. [manifest](https://github.com/denoland/std/blob/main/tar/deno.json), [UntarStream](https://github.com/denoland/std/blob/main/tar/untar_stream.ts).

## Implications for the OPFS plan

Keep transport/storage drivers, codec transforms, container readers, authenticated encryption framing, and optional preview renderers separate. User-created bridges should receive byte/range and credential capabilities explicitly, declare exact operations, own cancellation/disposal, and pass the same conformance fixtures. The existing OPFS `src/stream.ts` already carefully treats reader provenance, byte validation, iterator retirement, and terminal ownership; an archive extension must preserve those contracts rather than bypassing them with Blob/Response materialization or abandoned tees.

Promise a progressive preview ladder: identify format; inspect metadata; enumerate entries; read a selected entry; decode its content; render a bounded preview. Each stage reports required reads, unsupported capabilities, limits, and integrity/authentication state. An archive listing does not imply encrypted member readability. A range-friendly unencrypted index does not imply a whole-file authenticated ciphertext can safely expose an arbitrary plaintext range. Sequential TAR and gzip can stop early but cannot pretend to seek cheaply.

Before transfer, require focused tests for prefix replay and branch retirement, a slow consumer and oversized source chunk, byte/count/decompression limits, selected-member reads without complete extraction, cancellation during headers and member content, malformed/truncated headers, checksum/authentication failures, missing codecs, independent codec instances, precompiled-WASM injection, instance disposal, and root-versus-deep dependency graphs. Measure bytes fetched, bytes decoded, peak retained bytes, allocations/copies, time to listing/first preview, cancellation latency, and cold/warm initialization. Bundlejs's inspected registry-tarball test suite exercises package resolution and VFS extraction; it is not evidence for these OPFS guarantees. [registry tests](https://github.com/okikio/bundlejs-api/blob/34be097f00db4bf179b1dc08fc405dcad146905f/core/tests/19-registry-tarballs.test.ts).
